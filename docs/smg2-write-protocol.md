# SMG II 510 — 書き込みプロトコル

**出典: BMW 自身の SGBD `C:\EDIABAS\ECU\SMG2.prg` (535,906 B, 2021-09-18) を BESTDIS で逆アセンブルした
61,272 行。** テレグラムのバイト列は EDIABAS が実際に組み立てる定数そのもので、推測ではありません。
**推測が入っているのは §2.1 の索引対の読み方だけ**で、そこは ECU 側のコードで独立に確認しました。

再現手順は `tools/bestdis-note.md`。BESTDIS は .NET Framework 3.5 のままなので net9.0 へ移植して
ビルドし、CP1252 エンコーディングプロバイダを登録する必要があります。

## 1. 結論だけ先に

| 問い | 答え | 確度 |
|---|---|---|
| 消去・書き込みのサービス ID | **`0x07`**、サブ機能 `06`=消去 / `02`=書き込み / `0F`=終了 | **確定**（SGBD のテレグラム定数） |
| MSS54 (CSL ツール) と同じか | **同じ形**。`E46M3CSL_TuningTool` の `02`/`06`/`0F` と一致 | **確定** |
| Seed 要求 | `32 08 90 42 4D 57 05` — `42 4D 57` = ASCII **"BMW"** | **確定** |
| 高速化の目標値 | **125000 baud**（`SET_EDIC_BAUDRATE` に `48 E8 01 00` = 0x0001E848） | **確定** |
| **消去粒度** | プロトコルは範囲を指定しない。**ECU 側で決まっており、較正は `0x30000-0x3FFFF` の 64 KiB 1 セクタ** | **確定** → `docs/smg2-flash-driver.md` §2.2 |

最後の行が W0c への答えです。**「どの粒度で消えるか」は我々が指定するものではなく、ECU 側の
フラッシュドライバが決めます。**

そのドライバは読みました（`docs/smg2-flash-driver.md`）。**解決しました** —— 消去のセクタ表は
`0x00270`（プログラム 7 個）と `0x0028C`（較正 1 個）に素の物理番地で入っており、
較正セクタは **`0x30000-0x3FFFF` の 64 KiB** です。BMW 自身の `.0PA` / `.0DA` の開始番地と
二重に一致します。

## 2. テレグラム

DS2 の枠は `[ECU アドレス][全長][データ…][チェックサム]`。SMG2 の ECU アドレスは **`0x32`**。
全長にはアドレス・長さ・チェックサムを含みます。チェックサムはトランスポートが付けるので、
SGBD の定数には現れません。

| ジョブ | テンプレート | 読み |
|---|---|---|
| `SG_RESET` | `32 04 12` | サービス `0x12` = リセット |
| `BLOCKLAENGE_MAX` | `32 04 0D` | サービス `0x0D` = 最大ブロック長を ECU に聞く |
| `FLASH_LESEN` | `32 09 06 A2 A1 A0 -- 02` | サービス `0x06` = 読み出し（本ツールが既に使っている経路） |
| **`FLASH_LOESCHEN`** | `32 09 07 06 A2 A1 A0 LL` | **消去**。番地 3 バイト。`LL` は長さフィールドだが消去では 0 |
| **`FLASH_SCHREIBEN`** | `32 09 07 02 A2 A1 A0 --` | **書き込み**。この後にデータが続く |
| **`FLASH_SCHREIBEN_ENDE`** | `32 09 07 0F A2 A1 A0 --` | **セグメント終了** |
| `BAUDRATEN_UMSTELLUNG` | `32 08 91 00 25 80 03` | サービス `0x91`。`00 25 80` = 9600 (0x2580) |
| `SEED_KEY` | `32 08 90 42 4D 57 05` | サービス `0x90` + `"BMW"` |

### 2.1 番地の組み立て 【確定】

BESTDIS の逆アセンブルで、テレグラムのどのバイトが `BINAER_BUFFER` のどこから来るかが読めます。
`FLASH_LOESCHEN` / `FLASH_SCHREIBEN` / `FLASH_SCHREIBEN_ENDE` の 3 つとも同一:

```
テレグラム[0..3] <- テンプレート定数        32 09 07 xx
テレグラム[4]    <- BINAER_BUFFER[0x13]
テレグラム[5]    <- BINAER_BUFFER[0x12]
テレグラム[6]    <- BINAER_BUFFER[0x11]
```

バッファ側は `0x11,0x12,0x13` の並びで、テレグラムには **`[0x13][0x12][0x11]` の順**で入ります。
つまりバッファがリトルエンディアン 24bit なら、線上は **ビッグエンディアン MSB 先頭**。

**これは ECU 側のコードから独立に確認されました** (`docs/smg2-flash-driver.md` §4):
受信ハンドラは `DAT_00e014 = e060`（上位バイト）、`DAT_00e012 = CONCAT11(e061, e062)`（下位 16bit）
と組み立てており、番地はテレグラムのオフセット 4,5,6 に MSB 先頭で入ります。
BMW の SGBD と ECU のコードという二つの独立な経路が一致しています。

**訂正:** 8 バイト目 (`e063`) は**長さフィールド**です。初版は「長さを持たない」と書きましたが、
正しくは「フィールドは在り、消去では 0 が入る」。`FUN_002212` は `DAT_00e063 < 0x78` で
サービス全体を門番しています。消去が範囲を指定しないという結論は変わりません。

`FLASH_SCHREIBEN` だけ `[7] <- BINAER_BUFFER[0x0D]` と `[13] <- [0x07]`、`[21] <- [0x0D]` が追加され、
これがデータ長の取り回しです。

### 2.2 タイムアウトは操作ごとに違う 【確定】

各ジョブの先頭に `xsetpar` でインタフェースパラメータが置かれます。末尾 3 語がタイムアウト系:

| 文脈 | パラメータ | 読み |
|---|---|---|
| 通常（全ジョブ共通） | `… E8 03 32 00 14 00` | 1000 / 50 / 20 |
| `FLASH_LOESCHEN` 消去中 | `… 00 00 64 00 14 00` | 0 / 100 / 20 |
| `FLASH_LOESCHEN` 別相 | `… F4 01 19 00 14 00` | 500 / 25 / 20 |

**消去は待ち時間の設計が違います。** 通常と同じタイムアウトで消去を出すと、正常な消去を
タイムアウト扱いして再送しかねません。**消去は冪等ではないので、これは事故になります。**

## 3. MSS54 との比較

`E46M3CSL_TuningTool/src/lib/dme-link/webSerialDmeLink.ts` は MSS54 に対して
`02`=WriteSegment / `06`=EraseSegment / `0F`=FinishSegment を使い、**実車で書き込み実績があります**。

SMG2 も同じ 3 つのサブ機能を、同じサービス `0x07` の下に持っています。**形は同じ**。

ただし **同じであることと、同じ実装を流用してよいことは別**です。移植するなら
`link-measurement-and-safety.md` が実例として記録している事故 —— 読み取りチャンクのリトライだけ
移して書き込みチャンクのリトライを置き忘れた —— を踏まないよう、**隣接する保護もセットで**
移す必要があります。とくに §2.2 のタイムアウト差は MSS54 側には無い SMG2 固有の事実です。

## 5. この文書が変えたこと

計画 (`Phase W`) は「W1 = 手順の確定（車不要）」を残作業として挙げていました。**W1 は終わりました。**
そして副産物として、W0c（消去粒度）の性格が変わりました:

> 消去粒度は「先に特定する」ものだったが、**プロトコルには粒度という概念が無い**と分かった。
> 特定すべきは「我々が何を指定するか」ではなく「ECU が何をするか」であり、それは ECU の
> コードの中にある。

そのコードは読みました（`docs/smg2-flash-driver.md`）。結果は**半分解決**です:

- **確定**: 較正の消去は記述子 1 個ぶん。プログラム側は 7 個。較正であることは、同じ分岐が
  `seg3:0x2000` = `0x32000` を検査していることで決まる。
- **未確定**: その 1 個が何バイトか。**セクタ記述子はフラッシュではなく実行時の RAM にある**ため、
  静的イメージからは読めない。

**W0c は閉じました。** `preflight` の `erase-granularity` はもう塞いでいません ——
残る門番は ZB の申告とバッテリ電圧で、どちらも知識の欠落ではなく**その場の事実**です。
