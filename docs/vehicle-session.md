# 実車セッション手順（SMG II 抽出）

読み取りしかしないので ECU を壊す経路はありませんが、**測定値を残さない実行には意味がありません**。
各ステップの実測値をこのファイルの末尾に追記してください。通らなかったステップは
「通らなかった」と書きます — 走った実行を報告するか、何も報告しないかのどちらかです。

## 前提

| | |
|---|---|
| ケーブル | K+DCAN（FTDI）。E46 は **ピン 7 が K-line**、ピン 8 のジャンパは不要 |
| ポート | 9600 8**E**1。旧 PWA が 8N1 で開いていたのは既知の誤り |
| 車両 | イグニッション ON / **エンジン停止** / バッテリーチャージャ接続 |
| ブラウザ | デスクトップ Chrome か Edge（Web Serial） |
| 所要 | PROBE 数秒 + READ 2 パスで 24 KiB ×2 ≒ 2 分 |

読み出しは 1 テレグラムあたり要求 9 バイト + 応答 4+N バイト。9600 8E1 は 11 bit/char なので
実測 1.133 ms/char、ECU ターンアラウンドを足して **24 KiB ≒ 40–70 秒/パス**。

実測値（`f6de6103584b`、web-usb-ftdi、chunk 120）: **24,576 B / 205 テレグラム / 48.6 秒**。
= **1.98 ms/byte**。この係数から 512 KiB は **1,036 秒 ≒ 17 分**。
UI に出る「約 18 分」はこの実測からのスケールで、ボーレートからの理論値ではありません。

---

## 手順

### 1. 接続と身元確認

CONNECT → DEVICE タブの **MANUFACTURER DATA (DS2 0x53)** が返ること。

記録するもの:

- `HERSTELLER_DATEN_LESEN` の生バイト（画面からコピー）
- 期待する ZB 番号。基準車は **`7843260` / HW `2F` / SW `10`**
  （出典: `E46M3-Diagnosis/recordings/m3-smg2-real.json`、EdiabasLib 経由の実車記録）

**別の車なら ZB 番号は違います。** PROBE に渡す番号は、その車の SMG2 が名乗る番号です。
分からない場合は空のまま PROBE できますが、判定は「構造化データか否か」までしか下がりません。

### 2. PROBE — セグメントとベースアドレスの同定

hub の PROBE。10 候補（segment 0x00/0x01 × base 5種）を、各 48/60 バイトだけ読んで採点します。

**判定は一意です**: 正しい組でだけ `IDENT0`(`0x37FC0`) / `IDENT1`(`0x37715`) にその車の
ZB 番号が現れます。ここで 100% が 1 つだけ出れば確定。

記録するもの:

- 全候補のスコアと理由（DEVICE タブの一覧、そのまま貼る）
- 確定した `segment` / `base`

**2 つ以上が強く一致した場合**、ツールは選ばずに「曖昧」と報告します。ECU 側のデコードが
エイリアスしている可能性が高い。アンカーを増やして切り分けてから先へ進んでください。

**何も一致しなかった場合**、候補表（`packages/ds2-smg2/src/layout.ts` の
`CANDIDATE_SEGMENTS` / `CANDIDATE_BASES`）を広げます。これは読み取りだけなので安全に試せます。

### 3. READ — 2 パス

hub の READ。**同じ範囲を 2 回読んでバイト一致した場合だけ**ワークスペースに採用されます。
1 回では読み取りの正しさを主張できません（K-line が 1 バイト落とす、チャンクの off-by-one、
ECU が古いバッファを返す — どれも「開けるファイル」を作ります）。

記録するもの:

- 経過時間 / 交換回数 / リトライ回数（DEVICE タブの LAST READ）
- SHA-256（WORKSPACE カード）
- 一致したか（VERIFIED）

不一致だったら、その旨と最初に食い違ったオフセットを記録してから、ケーブルと接続を確認します。

### 4. サニティチェック — 最も安いのに最も効く

TUNE タブで次を目視:

| 項目 | 期待 |
|---|---|
| `Gear Ratios` | 6速の常識的な並び（4.23 / 2.53 / 1.67 / 1.23 / 1.00 / 0.83 付近）と Rear |
| `Rear Differential Ratio` | 3.62 か 3.15 付近 |
| `RPM Limit` | 8000 rpm 前後 |
| `AUTO: A1 Speed Thresholds` | 16×10 で単調に増える速度しきい値 |

**ここが物理的にあり得ない値なら、アドレス空間かエンディアンかスケーリングのどれかが違います。**
その場合、先に進まずに何が出たかを記録してください。

### 5. チェックサムの記録

`Checksum`(`0x32080`) の格納値を記録します。**これが算法同定の入力**です。
イメージが 2 本（できれば別車 or 別 SW）あれば、総当たりで
`sum16 / CRC-16(ARC, CCITT, MODBUS, XMODEM…) × 範囲 × LE/BE` を回して当てられます。
1 本で当たった候補は偶然の可能性があるので、2 本目で再現するまで採用しません。

### 6. エクスポート

ファイル名は `SMG2_510_PARTIAL24K_<日時>_<hash8>_NOCHECKSUM.bin`。
`NOCHECKSUM` は飾りではありません — **このビルドが出す BIN は書き込める BIN ではない**という
表明です。6 か月後にフォルダを見たとき、そこにある情報はファイル名だけです。

## 7. フルダンプ（512 KiB）

較正窓 24 KiB には**命令が 1 バイトも入っていません**。逆アセンブル、チェックサムの対象範囲、
`0x350D4` を誰がどう引いているか — これらはすべてプログラム領域を読まないと事実になりません
（`docs/undefined-tables.md` の「次に必要なもの」）。

### 段取り

| | |
|---|---|
| 所要 | **約 18 分**（1 パス）／ **約 36 分**（検証 2 パス） |
| 電源 | バッテリーチャージャ**必須**。18 分の IG ON はチャージャ無しでは回しません |
| 端末 | 画面はアプリがスリープさせません（Wake Lock）。ただし電源ボタンを押せば切れます |
| 検証 | 窓は既定で 2 パス。フルは**任意** — 2 本目はもう 18 分だからです |

### 手順

1. ハブが **READ** の面にあるとき、その上に出るチップで **`フル 512K · 約18分`** を選ぶ
   （チップは READ の面でだけ出ます。読み取り中に出ていれば、変えてはいけないものが
   変えられるように見えます）
2. 検証を付けるなら `検証（2 パス）` も押す。**36 分**になります
3. READ。ハブの通知が `割合 · バイト · テレグラム · リトライ · 残り時間` を出します。
   残り時間は**この読み取りが実際に出している速度**からで、9600 からの計算ではありません
   （2% 未満では出しません。そこでの推定はテレグラムごとに分単位で振れます）
4. 止めたくなったら **STOP**。ハブの右翼が読み取り中だけ STOP になります
   （切断は隠れます — 読み取りの止め方としてケーブルを抜くのは間違いで、
   18 分もあれば間違ったほうが使われます）

### 途中で落ちた / 止めた場合

**届いたバイトは捨てません。** 24,576 でも 524,288 でもない長さになるので、
どちらの MS4X 定義も当たりません。この状態を **生キャプチャ**として保持します:

- TUNE / COVERAGE は開きません（定義が無いものをデコードすれば、
  全アドレスが本来と違う位置を指した上で、値はそれらしく見えます）
- **EXPORT は効きます**。ファイル名は `SMG2_510_RAW<バイト数>B_…`
- **SYNC も効きます**（ワークス版）。D1 の `variant` 列は `raw` になり、完全なダンプと混ざりません

途中まででもプログラム領域が入っていれば逆アセンブルの材料になります。
18 分読んで最後のテレグラムで落ちたから全部捨てる、が一番損です。

### 記録するもの

- 実測所要時間・テレグラム数・リトライ数（ハブの通知と DEVICE の「直近の読取」）
- `Checksum` @`0x32080` の格納値が、512 KiB 全体を対象にした算法で当たるか
- `docs/undefined-tables.md` の未解決点: `0x35254` 以降のブロック境界
